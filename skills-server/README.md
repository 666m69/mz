# MZcode Skills Server

نواة خاصة للمالك لتسجيل إصدار مهارة، اختباره ثم السماح له بإنتاج مشروع ويب مستقل. ما يعمل اليوم هو القوائم المحلية للمهام والمشتريات، والعدّاد المحلي. النواتج ملفات HTML وJavaScript وCSS ووصف للمشروع داخل ZIP خاص.

## نتيجة التأسيس

| المرحلة | ما يمكن التحقق منه |
|---|---|
| المصدر | بُني الفرع على `6d4df891` من `feat/real-app-builder-v1-20261103`. يتضمن بوابة القدرات `bdffb2ae`. اجتاز محرك القوائم اختبارات الفرع الأصلية. |
| التحكم | Worker مستقل وملف ترحيل D1 إضافي. اختُبر نفس معالج الطلبات وعبارات SQL محليًا على SQLite، بما فيها المعاملات والتزامن وإعادة التشغيل. |
| التنفيذ | مشغّل Linux منفصل يستقبل عملًا واحدًا ويشغّل قالبًا مراجعًا ثُبّتت بصمته. سجل الاختبار الناجح شرط يسبق قرار المالك بالتفعيل. |
| التجربة | اختبار HTTP كامل لكل من التطبيقين، تنزيل ZIP، فحص محتواه ثم استخدامه في Chromium. تشمل الاختبارات واجهة المالك على عرض 360 بكسل ورفض فكرة تحتاج دفعًا أو تكاملًا خارجيًا. |
| الربط التجاري | الإنتاج، استقبال عملاء الموقع، البريد، التسعير، الدفع والنشر خارج هذه المرحلة. الربط يحتاج قرارًا مستقلًا من المالك قبل أي وصول لأفكار حقيقية. |

## تجربة محلية

يلزم Linux وNode 24 وPython 3.10+ و`libseccomp.so.2` للمشغّل. تتطلب اختبارات المتصفح Playwright وChromium موجودين محليًا. لا تتطلب النواة npm install أو خدمة مدفوعة. أمر التشغيل أدناه يربط الخادم على جهازه فقط.

```sh
node skills-server/dev/local.mjs
```

افتح `http://127.0.0.1:8791` على الجهاز نفسه. يعرض الطرفي التفاعلي رمز المالك ورمز المشغّل. أدخل رمز المالك في اللوحة. يخزن الخادم قاعدة محلية ومفاتيحها داخل `skills-server/.local-state/` بصلاحيات خاصة وخارج Git. يمكن اختيار دليل اختبار خاص باستخدام `MZ_SKILLS_STATE_DIR`، ومنفذ محلي عبر `MZ_SKILLS_PORT`. تحتفظ إعادة التشغيل بالسجل وبالطلبات. فقدان المفاتيح يوقف فك التشفير، فتُحفظ مع القاعدة في نسخة احتياطية خاصة. إذا وُجدت القاعدة دون مفاتيحها يرفض الخادم استبدالها.

1. اختر مهارة وتنفيذًا مراجَعًا، ثم اسمًا عربيًا ورقم إصدار مثل `1.0.0`. اضغط **إرسال للمراجعة**.
2. في طرفية ثانية على الجهاز نفسه، شغّل عملاً واحدًا بالرمز الخاص بالمشغّل. لا تكتب قيمته في الأمر أو في Git.

```sh
export SKILLS_URL=http://127.0.0.1:8791
read -rsp 'Runner token: ' SKILLS_RUNNER_TOKEN; echo
export SKILLS_RUNNER_TOKEN
python3 -B skills-server/runner/agent.py --probe
python3 -B skills-server/runner/agent.py --once
```

3. اضغط **تحديث الحالة**. بعد نجاح الاختبار يظهر **تفعيل**. يمكن تعطيل المهارة أو التراجع إلى الإصدار السابق الذي اجتاز الاختبار. لا يُفعّل إصدار تلقائيًا.
4. تجري التجربة الشاملة أدناه الاستقبال الخاص ثم جدولة البناء ثم تنزيل ZIP. لتشغيل ZIP بنفسك، فكّه في دليل منفصل وشغّل `python3 -m http.server 8000 --bind 127.0.0.1` فيه وافتح `http://127.0.0.1:8000`. احفظ كل مشروع تحت أصل محلي منفصل عند العمل على أفكار خاصة. لا يُقدَّم HTML الناتج من أصل لوحة المالك.

## العمليات الداخلية

كل طلب API يحتاج رمز Bearer. تُرفض الطلبات من أصل أجنبي، ويُطلب HTTPS خارج loopback. المالك وحده يراجع ويُفعّل ويُعطّل ويتراجع. رمز الطلب مقصور على طلب واحد. رمز المشغّل يطالب بعمل من الطابور ويسجّل نتيجته فقط.

| العملية | المسار | صلاحية الوصول |
|---|---|---|
| سجل الإصدارات والعقود وحدود التنفيذ والاختبارات | `GET /api/skills` | المالك |
| تسجيل إصدار جديد وإضافة اختبار آلي | `POST /api/releases` | المالك |
| تفعيل، تعطيل، تراجع | `POST /api/skills/{id}/{activate,disable,rollback}` | المالك مع رقم المراجعة الحالي |
| استقبال فكرة خاصة وتوليد رمز طلب محدود | `POST /api/requests` | المالك بعد تسجيل موافقة صاحب الفكرة على نموذج خاص |
| عرض حالة الطلب وتشغيلاته | `GET /api/requests/{rid}` | المالك أو رمز الطلب نفسه |
| تشغيل الإصدار النشط وتثبيته للطلب | `POST /api/requests/{rid}/runs` | المالك أو رمز الطلب نفسه |
| نتيجة التشغيل أو ZIP للتنزيل | `GET /api/requests/{rid}/runs/{jid}` و`.../{jid}/artifact` | المالك أو رمز الطلب نفسه |
| سحب مهمة، تسليم نتيجة | `POST /api/runner/claim` و`POST /api/runner/jobs/{jid}/complete` | المشغّل |
| الأعطال والمهل وأحداث التدقيق | `GET /api/monitor` | المالك |

مثال لبيانات استقبال اصطناعية. يعيد المسار `request_id` و`request_token`. يرسل العميل `{}` إلى مسار التشغيل، ثم يتابع `id` حتى يظهر `succeeded`. تتطلب عمليات التغيير `Idempotency-Key` ثابتًا عند كل إعادة محاولة، بطول 12–80 محرفًا. سحب الطابور يستخدم عقد إيجار ذريًا مستقلاً.

```json
{
  "skill_id": "local-checklist",
  "input": {"idea": "أريد قائمة مشتريات أسبوعية أحفظها على هذا الجهاز", "title": "مشترياتي"},
  "private_prototype_consent": true
}
```

الموافقة المسجلة تخص بناء نموذج خاص فقط. يسجل المالك موافقة صاحب الفكرة ويحتفظ بمرجعها خارج هذه التجربة قبل إدخال بيانات حقيقية. لا توجد عمليات للتسعير أو الدفع أو النشر أو منح حقوق إعادة استخدام الفكرة. تُشفّر المدخلات والنواتج بـ AES-GCM مع معرّف الطلب أو التشغيل في بيانات المصادقة. يسجّل سجل التدقيق نوع الحدث ومعرّفه وتوقيته. لا تُنسخ الفكرة إلى السجل أو Git أو ملفات التطبيق. يمكن أن يظهر اسم التطبيق الذي اختاره العميل داخل ملفاته الخاصة.

## معيار علامة MZcode — تنفيذ جديد v2

بناءً على قرار المالك، أُضيفت **نسختان جديدتان لمخرجات التطبيقات بعلامة MZ الأصلية** دون تعديل ملف الشعار أو قوالب v1 أو بصماتها:

- `local-checklist / checklist-branded-v2`: يدعم منظم المهام والمشتريات كما هو، مع تضمين ملف `site/assets/images/mz-mark.svg` الأصلي داخل `index.html`.
- `local-counter / counter-branded-v2`: عدّاد محلي مستقل بنفس علامة MZ الأصلية.
- يحتفظ كل مشروع بأربعة ملفات فقط (HTML وCSS وJS وblueprint) وبحد 48 KiB، دون صور خارجية أو اتصالات إضافية أو تغيير في بيانات المستخدم.
- `reviewed.json` يضم تنفيذ v2 ببصمة جديدة مثبتة. بقي `default_adapter` للمهارتين v1، وهو مسار تراجع صالح. **لم يتم تفعيل أي إصدار v2 تلقائيًا**.
- فحص البصمات القديمة والجديدة مطابق لعقد `agent.py`. فحوص `skills-server/test/brand-v2.test.mjs` تؤكد شعار MZ المرئي، سلامة الأربعة ملفات، صلاحية الأداء المحلي، ورفض فكرة تتطلب شبكة أو دفعًا.
- ثبت اجتياز **5/5 اختبارات** في سجل بناء معاينة Cloudflare على الفرع المنفصل بتاريخ 5 نوفمبر 2026. لا تعني هذه الفحوص نشر Skills Server أو اختبارات عزل Node 24 الكاملة؛ يظل تشغيل النواة خلف حماية المالك فقط وفي بيئة منفصلة.
- عند نشر مهارة v2 مستقبلًا: يسجّل المالك إصدار `2.0.0` ويختاره بمراجعته، يختبره المشغّل المعزول، ثم يفعّله يدويًا. لا تدخل أفكار عملاء حقيقية قبل تصريح منفصل.

## إصدار مهارة وتطويرها

- يتضمن كل سجل `id, name_ar, version, input_schema, output_schema, permissions, limits, test_status, enabled, rollback_version`، إضافة إلى بصمة التنفيذ. الإدخال عقد مغلق يرفض الخصائص غير المعروفة. الإخراج ملخص تحقق يحوي بصمة الملفات الأربعة وعددها وحجمها.
- لتحديث البيانات الوصفية، سجّل إصدارًا جديدًا من تنفيذ موجود وراجعه ثم فعّله. لا يمكن تعديل عقد أو بصمة إصدار سبق إنشاؤه. يبقى الإصدار العامل فعالًا أثناء اختبار الجديد.
- لتنفيذ جديد، أضف محولًا وقالبًا واختبارات سلوكية كملفات مصدر مُراجعة، ثم مرجعًا جديدًا في `reviewed.json`. ابقِ ملفات التنفيذ القديم ومراجعه متاحة لدعم التراجع. لكل مرجع مخطط مدخلات مستقل ونقطة دخول وملفات ثابتة. تشمل البصمة أسماء الملفات ومحتواها ونقطة الدخول والمخطط والحصة اليومية. يقبل العدّاد عدد بداية اختياريًا بين 0 و9999، وترفض القوائم هذا الحقل. استخدم `python3 -B skills-server/runner/agent.py --fingerprints` لمراجعة البصمات. تعديل تنفيذ أو اختبار قديم يرفض تشغيله عند اختلاف بصمته.
- تستخرج اللوحة الخيارات من قائمة التنفيذ المراجع. لا توجد واجهة لاستيراد كود أو إدخال رابط حزمة أو أوامر. يستطيع التنفيذ المراجع تعريف حقول نصية وصحيحة خاصة به داخل مخطط المدخلات. أي تغيير في أنواع التحقق المدعومة أو صيغة الناتج يحتاج مراجعة عقد المنصة وحدودها واختبارهما قبل إصدار جديد.
- يتحقق المشغّل في مراجعة كل إصدار من بنية العينة ورفض المدخلات السلبية ووجود ملفات مستقلة وتغيير حالة التطبيق واستعادتها. يتحقق كذلك من سلوك كل ناتج فعلي قبل تسليمه. يختبر Chromium المسارين كاملين في اختبارات القبول. يظل المشغّل جهة ثقة منفصلة، ويثبت مفتاحه هويته للـWorker.

## التشغيل والعزل

الـWorker يدير السجل والموافقات والطابور ويغلف الملفات الموثقة للتنزيل. لا يشغّل Node أو shell أو نص الفكرة. ينسخ المشغّل المصادر المثبتة إلى دليل مؤقت لكل عمل، ثم يشغّل Node مباشرة ببيئة نظيفة وبدون مفاتيح. يسمح Node بقراءة المصادر وقراءة أو كتابة دليل الناتج. يحظر المشغّل الشبكة على مستوى نداءات النظام باستخدام seccomp، ويمنع Node تشغيل العمليات الفرعية والملحقات. يُختبر الحظر فعليًا. تقتصر هذه الحدود على القوالب المراجَعة. لا يدعم هذا المسار تشغيل JavaScript عشوائي أو تثبيت حزم الزوار.

| الحد | القيمة المطبّقة |
|---|---|
| لكل محاولة | 6 ثوانٍ جدارية، ثانيتا CPU، 768 MiB مساحة عناوين، 32 MiB لسقف V8 old-space |
| الناتج | أربعة ملفات ثابتة الأسماء، إجمالي 48 KiB لكل مشروع |
| التزامن والاستعادة | مشغّل واحد يملك عقد إيجار حيًا، مدة العقد 30 ثانية، محاولتان ثم فشل ظاهر في المراقبة |
| الطلبات اليومية | 24 استقبالًا و24 مهمة إجمالية تشمل اختبارات الإصدارات، بحسب UTC |
| طلب واحد ومهارة واحدة | 3 عمليات بناء لكل طلب، 8 عمليات بناء لكل مهارة يوميًا |
| الطابور واحتفاظ التجربة | 8 مهام معلقة كحد أقصى، 400 طلب و400 مهمة إجمالية قبل إيقاف الاستقبال أو التشغيل عند بلوغ حده |
| حدود الواجهة | 90 طلبًا في الدقيقة للمالك، 120 للمشغّل، 40 لكل رمز طلب صالح |

التعطيل أو تبديل الإصدار يسحب الأعمال المعلقة للإصدار المسحوب. نتيجة المشغّل المتأخرة ترفضها قاعدة البيانات، بما في ذلك عند انتهاء عقد الإيجار قبل وصول مشغّل آخر. لا تحذف النواة مشاريع أو طلبات قائمة. تُعرض الأعطال والانتظار محليًا. يحتاج التشغيل المستمر لاحقًا إلى جهاز Linux موثوق متاح ومشغّل مراقَب؛ الأمر `--once` يعالج عملًا واحدًا ثم يخرج.

## إعادة الاختبار

```sh
npm test
node --test skills-server/test/*.test.mjs
python3 -B skills-server/test/isolation.py
node --test skills-server/test/e2e.mjs
```

يحتاج الأمر الأخير حزمة Playwright ومتصفح Chromium. إذا كانا منصبين خارج المشروع يستخدم الاختبار `PLAYWRIGHT_MODULE` و`CHROMIUM_PATH`. يمكن ضبط `MZ_EXAMPLE_DIR` لدليل خاص فارغ لتصدير ملفي ZIP الاصطناعيين. لا تضف الناتج أو الرموز إلى Git. تقرير نتائج التشغيل الفعلي في [ACCEPTANCE.md](./ACCEPTANCE.md).

## Cloudflare والنشر

`wrangler.local.jsonc` إعداد محلي باسم مستقل ومعرّف D1 غير مرتبط بأي حساب. لا مسارات أو Workers.dev أو Preview URLs. مرفق الترحيل للقاعدة الجديدة فقط. لا يوجد backfill ولا تغيير للموقع التجاري أو قواعده. تعتمد الاختبارات المحلية على محول معاملات يستخدم SQLite الحقيقي وتعمل عبر HTTP، ولم يُطبّق الترحيل على D1 مستضاف.

للتحقق التالي يلزم نطاق اختبار خاص مستقل، وإثبات الحصة المجانية وصلاحيات إنشاء Worker وقاعدة D1 منفصلة، ومشغّل موثوق. تتطلب بيئة التحكم الأسرار `OWNER_TOKEN_SHA256` و`RUNNER_TOKEN_SHA256` (ملخص رمزين مستقلين عشوائيين) و`CAPABILITY_KEY` و`DATA_KEY` (مفتاحان مستقلان من 32 بايت بترميز base64url). يضبطها المالك كأسرار للخدمة المنفصلة فقط. تدوير مفتاح البيانات يحتاج إجراء إعادة تشفير مدروس، وتدوير مفتاح صلاحيات الطلبات يبطل الرموز الموجودة. لا تُعاد تسمية أو مشاركة قاعدة الأفكار أو مفاتيح الموقع. لا يوجد تسعير أو نشر تلقائي في الفرع.
